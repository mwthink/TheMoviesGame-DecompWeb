# Awards, achievements and the award bonuses

The award ceremonies, how award scores are gathered, rank prizes, the award bonus table, and the Super Star / Midas Touch boosts. Companion to `MOVIE_SUCCESS.md` (the box office the awards react to) and `STARS.md`. Labels: **[code]**, **[data]** / **[config]** (ini), **[measured]** (logged from the running game). Section labels (3k, 3aa, ...) are stable identifiers that other documents and code comments cite; they are not a reading order.

**Gameplay bonuses (player's screenshot, HUD "Awards" panel, "Bonuses will remain active until the next Awards Ceremony")**: after this ceremony the game listed exactly four active bonuses - **Trend Setter** ("boosts the public's interest in your movies regardless of genre"), **Party On** ("stars can eat and drink without fear of addiction"), **Age of Discovery** ("scientists will research faster") and **Easy To Please** ("stars hard to offend and easy to please") - one per award won, which confirms the award -> bonus table above and that **bonuses last until the next ceremony**; the panel also says the next ceremony is on **1 January 1940**, i.e. ceremonies are **every five years** (1935, 1940, ...). Only three of the four appeared in the 12 flags logged (10, 11 and 8), so Party On is probably flag 8 and Easy To Please has an index of 12 or above.
**Trend Setter validated numerically**: after the ceremony the log shows `GP = 1.1593` for horror (saturation 0.1697) and `GP = 1.1405` for romance (saturation 0.2478). With the bonus the trend is forced to 1.0 (`trendsetter_boost`, replacing the audience-taste trend, `MOVIE_SUCCESS.md` 3e/3f): `GP = (0.9 + 0.3*1.0) * (0.8 + 0.2*(1 - saturation)) = 1.2 * 0.96606 = 1.1593` and `1.2 * 0.95044 = 1.1405` - **both exact**. (Before the ceremony the same genres had trends near 0.1 and `GP` about 0.93.) So while Trend Setter is active every genre gets the maximum 1.2 popularity factor, and only saturation differentiates them.
Consequence for planning: a movie's chance at MOVIES_FIRSTPLACED is exactly its star rating `0.73*S + 0.33*Qm`, i.e. **box-office success dominates**; the studio that wins gets the bonus that applies to the *next year's* production.

### 3k-3. Award score sources (decoded from the gather functions) **[code]**
Each category's factory (vtable slot 9) loops over a global list and pushes `(contender, score)`: **Highest Charting Star** (0x8686C0) -> the entry's contender is the star's owner studio (`star+0x934`, `CStar_GetOwnerStudio`; an earlier version of this document called it a chart score, which was wrong) and the score is the value returned by the list entry's own virtual slot 6, not a field of the star; **Most Prestigious Studio Lot / BestLot** (0x8699C0) -> loops the studio list `0x104BCF0` and uses studio vslot `0x80` (the slot that holds `CStudio_GetMoneyRatingComponent`, i.e. a wealth-based 0..1 value that goes through the `0x104BD38` money thresholds - so "lot prestige" is probably the **money component of the studio rating**, not the lot buildings; the AI default 0.70 is its starting value); **Highest Charting Studio** (0x8691D0) and **Highest Climbing Studio** (0x869300, score = `vslot 0x1C - vslot 0x28 + float`, only entered if >= 0) loop the manager `DAT_00f88fa8` list (+0x98) and read league-entry vslots 0x18/0x1C/0x28/0x30 (not yet decoded). Studio rating itself = reputation `CStudio_GetDecayedReputation` (`repBase * 2^(-k*(now-repTime))`, +0x138/+0x13C) + money component + awards component (`CStudio_GetAwardsRatingComponent` = number of awards owned * constant), combined in `CStudio_ComputeStarRating`. Studio vtable slots 6/7 are AddMoney/SubtractMoney (`CStudioAI_AddCapital` +0x218 / `CStudioPlayer_AddMoney` via finance object).

### 3k-4. 1945 ceremony and the first PR-marketed release (measured) **[measured]**
**Public interest with PR validated exactly.** Release at 1944.96 (action, marketing level 3): `Qm = 0.6974`, `hype = 0.3082`, `D = 0.3459`, logged `PI = 1.3687`. Model: `D' = min(D, Qm/2) = 0.3459`, `hypeCapped = 0.3082`, `s = 0.6541`, `cover = s/Qm = 0.9379`, `imbalance = |0.3082-0.3459|/0.6541 = 0.0576`, `F = (1-0.3*0.0576)*0.9379 = 0.9217`, `PI = 1 + 0.4*F = 1.3687` - **exact**. Whole success: `P = 1.1*0.9390*1.0715*0.9107*1.3687 = 1.3796`, `x = ((P-1) - 2*(Qm-0.5)*0.12)*0.8 = 0.2658`, `g = 0.08 + 0.064 + 0.0658*0.512 = 0.1777`, `S = Qm + g = 0.8751` (logged 0.87502) - **exact**. Payout rate: `dailyPct = 0.013*(0.4+0.6*s) = 0.010302` and `dailyMul = 1-0.004*(0.4+0.6*s) = 0.99683`, both exact (without PR: 0.0052 / 0.9984). So the PR release gained `+0.18` success (0.70 -> 0.875), about 2.1x the revenue pool (1.14M vs 0.54M). Open: `D = 0.3459` is not `(1-Qm)*level_factor` for any table value with the final Qm (0.3026*0.5 = 0.15); D is probably computed from a different quality (an earlier estimate) or a different level table - to check with the next PR release (log has `marketingLevel` and `D`).
**Pioneer window confirmed again:** TP stayed 1.100 at 1944.96 after the 1944.09 expiry, because the item `0x1D343E30` (natural date 1954.085) was finished at 1944.08 (effective date 1943.99 -> 1944.09, i.e. it passed "now" just before the old item expired), so the window now runs to **1954.09**. (The 1964.10 item is not the one in effect.)
**1945 ceremony** (every 5 years; 1 January): the player won categories 0 (star), 6 (studios first), 12 (movie, their action movie `0.8689` = its star rating `0.73*min(1,S)+0.33*Qm` again), and the new category **11 = STUDIOS_BESTEMPLOYER** (score 0.797), and lost 10 (an AI studio scored 0.909), 7 (climber, AI 3.11) and 5 (most prolific star, 5 films). ### 3k-7. Lifetime achievement checks (decoded) **[code]**
All checks compare against `LifetimeAward_GetCachedThreshold` (read once from `global.ini [awards]`) with `threshold <= value`: **CashRich** = player's balance (vslot 0x24); **MoneyMaker** = lifetime box-office income (finance +0x120); **StarMilestone** = rating of the player's best star (`PlayerStudio_GetBestStarByRating` -> `TMCharacter_GetStarRating`); **StudioMilestone** = studio vslot 0x84 value (the studio rating); **MovieMilestone** = highest `+0xB4` value among the player's league-table movie records (almost certainly the movie star rating `0.73*min(1,S)+0.33*Qm`, the same number the awards and release screen use; not directly verified); **HighlyProlific** = number of player movies (`PlayerMovies_Count`, list `0x104D728`); **BigOutput** = *sum of the `+0xB4` values of all player movies* (so it is a sum of movie ratings, not of final qualities); **ConsistentQuality** = number of player movies whose `+0xB4` value is >= the quality bar (0.4/0.6/0.8; needs 5 such movies); **Awards** = lifetime awards won; `MovieRatingThresholdAward` (a per-project variant with threshold +0x30) checks `CProject_GetStarRatingOrQuality >= threshold`. Consequences: milestone level 4 needs a perfect 1.0 rating (star, studio or a single movie with `0.73*min(1,S)+0.33*Qm >= 1`, i.e. S >= 1 and Qm >= 0.82), and Big Output 30 needs about 40 movies at 0.75. From the logged releases the player's movie ratings were: 18 movies, sum 8.67, best 0.8689, count >= 0.4: 11, >= 0.6: 4, >= 0.8: 1.

## 3l. Pioneer technology window (decoded + validated against the RESEARCH log) **[code + measured]**
`CStudioPlayer_HasActivePioneerTechnology(date)` (0x518D00) walks the research item list and returns true if **any** item satisfies: `item+0xA0 == category of "moviemaking"` (category id 0 in the log; the log shows categories 0..3 and only 0 counts), `item+0x10B == 0` (item is part of the tree / not locked), `item+0x134 <= date` and `date < item+0xA4`. Meaning of the two dates (float game-days, shown as years in the log): **`+0xA4` is the technology's natural availability date** (fixed, e.g. 1940.129, 1944.091); **`+0x134` is the effective date, which starts equal to `+0xA4` and is pulled earlier while the player researches it** (it drops continuously, about 5 game-years per real game-year of research, e.g. 1942.64 -> 1942.19 -> 1941.73 over three months). As soon as the effective date passes the current date the technology is usable *before its time* and the movie gets **TP = 1.1** until the natural date arrives; after that the bonus ends unless another moviemaking technology is ahead of its time. Validation: TP was 1.0 at 1930.02 and 1.1 at 1931.75 (item with `+0x134` = 1930.525, `+0xA4` = 1934.052), 1.1 at 1934.01 (same item), 1.1 at 1934.99 .. 1939.80 (item `+0x134` = 1934.729, `+0xA4` = 1940.129), and 1.0 for the 1927-1930 releases. Correction after the user reported being ahead in research: a second moviemaking item (`0x1D343458`, natural date 1944.0905) reached its effective date at 1936.25, so the bonus runs until **1944.09** (the latest natural date among finished items), not 1940.13. The user's 'technology that unlocks in 1961' does not match any logged moviemaking natural date (nearest 1954.09 / 1964.10) - needs the technology's name or the next research log to identify; RESEARCH changes are only logged when an item changes, and no category-0 item changed after 1936.33. Practical rule: research a moviemaking technology early (the earlier you finish it relative to its `+0xA4` date, the longer the 10% success bonus lasts).

## 3s. Super Star / Midas Touch quality boost (decoded) **[code]**
The two quality flags in the REL_PLAYER log (`boostStar` at project `+0x40D`, `boostDirector` at `+0x40E`) are tied to **the specific person who won the award**, not to the studio. `AwardBonuses_RecomputeActiveFromWinners` records the star who won the star-acting award (`AwardBonusManager_SetSuperStarWinner`, bonus 5) and the winner of the directing award (`..SetMidasTouchWinner`, bonus 2). `CStar_SetCurrentProject` runs whenever that person is assigned to or removed from a project: if bonus 5 is active and the person is the stored Super Star winner, the project's `boostStar` flag is set (cleared on removal); likewise bonus 2 and `boostDirector` for the director winner. `CProject_GetQualityWithAwardBoost` then returns `clamp01(quality + bonusValue)` where `bonusValue` is `acting_boost` 0.04 for Super Star (checked first) **or** `directing_boost` 0.04 for Midas Touch - the two never stack, so the maximum boost is +0.04 final quality (this getter is the quality the success model uses: it is called by `CProjectSuccess_Recompute` (twice), `CProject_GetCappedHype`, `CProjectSuccess_ComputeCastStarRatingsFactor`, `CProject_ComputeMovieStarRating`, `CProject_GetStarRatingOrQuality`, `CProject_FinalizeRelease` and by the reviews and release screen - so the `Qm` of every formula in this document is the boosted quality, and with a boost flag set the movie's S, hype cap (Qm/2), star rating and award score all rise; in the logged releases the flags were 0 so Qm equalled the raw quality snapshot). It lasts until the next ceremony (bonus flags are recomputed every 5 years) and applies only to projects the winner is attached to. All logged player releases so far show both flags 0 because the star-acting and directing awards did not appear in the 1935-1945 ceremonies logged so far (they are probably unlocked later by `Award_GetAvailableFromYear`).

## 3t. Award availability schedule (`Data/awards.ini`, `available_from`) **[config; matches the 1935/1940/1945 logs]**
Ceremonies every 5 years from 1 January 1925; an award is judged from the first ceremony at or after its year, with its bonus: **1925** Highest Charting Star (Trend Setter), Highest Charting Studio (Half Price), Highest Charting Movie (Easy To Please); **1930** Most Prestigious Studio Lot (Age of Discovery); **1935** Highest Climbing Studio (Party On); **1940** Most Prolific Star (Perfect Fit); **1945** Best Employer (Brainwasher); **1950 Best Director (Midas Touch, the +0.04 director quality boost)**; **1955** Best Newcomer (Quick Learner); **1960** Most Prolific Studio (Free Love); **1965 Best Actor (Super Star, the +0.04 acting boost)**; **1970** Highest Climbing Star (No Worries); **1975** Studio Quality Output (On The Radar, doubles PR awareness); Best Script (Feeding Frenzy) is set to 3000, i.e. never; the three stunt awards (Lucky Charm, Natural Talent, Thick Skin) become available 5 / 10 / 15 years after stunts start (`available_post_stunt`). `tally_threshold` (5, 5, 5, 13, 2, 3, 5, 5, 2, 2, 5, 2, 2) is the number of wins needed for each award's lifetime-award upgrade (gold/platinum tiers, `ranking.ini` [21]/[22]). So the 1945 ceremony in the log had exactly the seven categories 0, 6, 12, 10, 7, 5, 11 (new: Best Employer), and the next one (1 January 1950) adds Best Director.
